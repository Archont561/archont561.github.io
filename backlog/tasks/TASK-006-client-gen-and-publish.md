# TASK-006 — Client generation pipeline & npm publish (M3)

Status: todo · Depends on: TASK-004 · Blocks: M3 exit · Decision: [D-004](../decisions/D-004-github-app-client-npm-package.md)

## Acceptance criteria

- `packages/github-app-client/src/client/**` is generated by `bun openapi-ts`
  from the worker's checked-in `openapi.json`; checked in for review; stale
  markers (`@hey-api/openapi-ts`, `Generated clients are derived`) fail `bun run check`.
- `turbo run generate` (plain task + `dependsOn: ["@archont561/github-app#openapi"]`)
  rebuilds the spec first; `bun run dev`/`test`/`build` depend on `generate`.
  `dist/**` builds before any in-repo consumer compiles (`^build`).
- Package publishes `@archont561/github-app-client` to npm: `bunup` build
  (`dist/` + generated `index.d.ts`, `exports()` plugin keeping the exports map
  in sync), `publishConfig.access = public`, `files: ["dist"]`, private
  `@archont561/tools` inlined via `noExternal` and absent from the published
  manifest; `@hey-api/openapi-ts` runtime remains a real dependency.
- `.github/workflows/publish-client.yml` publishes on version tags with
  npm provenance (DOC-009); release tagging is the portfolio's upgrade path.
- Cucumber smoke: mock worker API round-trip through the generated SDK
  (language-agnostic, idempotent-safe); TS types resolve via `@/*` aliases
  (package root) in bunup + typescript.

## Non-goals

- Polling transports, retry policies, transport-specific bindings (M4).
- Publishing `@archont561/tools` (inlined, never published).
